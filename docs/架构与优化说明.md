# 架构与优化说明

## 1. 为什么选择 ComfyUI 量化路线

单台 GB10 的优势是 128 GB 统一内存，可容纳大权重；限制是内存带宽、统一内存竞争和长序列 full-attention 开销。官方 4 GPU BF16 路线面向多卡并行，不适合作为单 Spark 首次部署。

量化组合将模型文件控制在约 42.5 GB，为以下内容留下空间：

- 操作系统和 Docker；
- CUDA context；
- Qwen3-VL 编码；
- 视频与音频 VAE；
- diffusion 激活；
- full-attention 临时张量；
- 输出编码和文件缓存。

## 2. 基础镜像与稳定应用依赖

升级目标使用 NGC PyTorch 26.10 的 ARM64 镜像作为 GPU 基础环境。镜像内的 NVIDIA 定制 torch 为开发版；应用在 `/opt/h3-venv` 中安装上游正式版 PyTorch 2.15.0，并与 NGC Python 扩展隔离。

ComfyUI 使用 v0.45.0 正式 release，直接依赖的稳定版本固定在 `docker/requirements-stable.txt`，安装后执行 `pip check` 并保存完整包清单。ComfyUI 音频功能使用 `comfy.audio`，不再额外安装 torchaudio。

GPU 可用、音频算子、节点加载、真实模型生成分别验收，镜像的新版本号不代表所有验证自动通过。

### 2026-11-11 版本核对

| 组件 | 固定版本 / 处理方式 |
|---|---|
| NGC 基础镜像 | `26.10-py3`，使用 ARM64 镜像 |
| ComfyUI | `v0.45.0` 正式版 |
| 应用 PyTorch / torchvision | `2.15.0` / `0.29.2`；独立 venv，未使用 NGC 的 `a0` torch |
| 前端 / 工作流模板 / 内嵌文档 | `1.58.7` / `0.11.106` / `0.5.16` |
| comfy-kitchen / comfy-aimdo | `0.2.41` / `0.6.0` |
| Transformers / Tokenizers / Safetensors | `5.22.2` / `0.23.3` / `0.8.0` |
| NumPy / SciPy / Pillow / PyAV | `2.5.4` / `1.18.1` / `13.0.0` / `19.0.2` |
| torchaudio | 删除；ComfyUI H3 使用内置 `comfy.audio` |
| GitHub Actions checkout | `v7.0.1` |

34 个直接依赖逐项核对 PyPI 正式发布版本及 Python 3.12 / ARM64 wheel；包括间接依赖在内共锁定 103 个包，并使用官方 PyPI 文件 SHA-256 校验。完整清单见 `docker/requirements-stable.txt` 与 `docker/requirements-lock.txt`。间接依赖服从上游版本约束，不能逐项强制覆盖成不兼容的版本。

Python、CUDA 工具链、FFmpeg 等系统组件沿用所选 NGC / Ubuntu 软件源；PyTorch wheel 自带的 CUDA 运行库与基础镜像工具链分别记录。宿主机驱动、Docker 和 NVIDIA Container Toolkit 不属于应用依赖，本次没有修改。模型权重按 ModelScope 清单的文件大小和 SHA-256 固定，不能用应用版本号推断模型有更新。

版本依据：[ComfyUI release](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.45.0)、[NGC 26.10 release notes](https://docs.nvidia.com/deeplearning/frameworks/pytorch-release-notes/rel-26-10.html)、[PyTorch PyPI](https://pypi.org/project/torch/2.15.0/)、[checkout releases](https://github.com/actions/checkout/releases/tag/v7.0.1)。版本核对不等于完整 H3 工作流已通过，运行结果单独记录。

## 3. 为什么默认 `cache-none`

H3 的权重已经较大。缓存模型中间结果可提高重复工作流速度，但会挤占统一内存。建立稳定基线时，优先可预测性，而非首轮极限速度。

## 4. 为什么默认不安装第三方节点

第三方节点可能：

- 自动安装并覆盖 torch；
- 编译不支持 SM121 的 CUDA 扩展；
- 引入未经验证的 Triton/SageAttention；
- 改变节点参数或工作流兼容性。

完成官方 T2V 基线后，再按“一次一个节点、单独镜像层、可回滚”的原则扩展。

## 5. 后续优化优先级

```text
P0：稳定运行与可复现
P1：分辨率/时长边界测试
P2：冷启动与热启动测量
P3：SageAttention 的 SM121 源码构建验证
P4：队列、API、鉴权和任务持久化
P5：官方 sparse-attention 权重/实现发布后的升级
```

## 6. 不建议的优化

- 把系统 Swap 当作额外显存；
- 一次性将所有模型常驻内存；
- 用 0.0.0.0 无鉴权暴露公网；
- 在运行容器中随意 `pip install -U torch`;
- 未记录参数就同时修改分辨率、时长和卸载策略；
- 首次测试直接 15 秒、1344×768。
