## 3. 测试规则

1. 每次测试前停止其他大模型容器。
2. 使用同一提示词、Seed、采样参数。
3. 第一次运行视为冷启动，另行标记。
4. 至少记录一次热启动。
5. “成功”要求输出可播放、画面非黑、有音频、服务未退出。
6. 只改变一个因素：分辨率、时长或内存参数。
7. 出现 OOM 后先采集诊断，不立即尝试更大任务。

分层验证结果：

- NGC 原生 torch：CUDA FP32/BF16 矩阵乘、BF16 卷积、注意力与 MATH 对照、`comfy.audio` 重采样和 Mel 谱全部通过。
- 应用稳定版 torch：上述算子全部通过，确认导入路径为 `/opt/h3-venv`。
- 真实 H3 音频 VAE：严格加载模型状态，CUDA decode 输出 `[1,2,6400]`，encode 返回 `[1,32,2,8]`，均为有限值且非静音。
- ComfyUI：HTTP 服务就绪、所需 H3 节点注册、完整 20 步采样与音视频输出通过；最终自动化退出码为 `0`。
- Python 依赖：103 个包安装后 `pip check` 通过。cuSPARSELt 0.8.1 仅修正已确认的 ARM wheel 平台元数据，原生库未修改，调整记录保存在镜像 `/opt/h3-runtime-adjustments.json`。
- 本地检查：19 项回归测试、ShellCheck、Python 语法、Compose 配置和 `git diff --check` 通过。

生成测试镜像 ID 为 `sha256:5503d952eef929dda230e03addf1fa2656c26b8260795e84ec4a237d4000eba7`。随后仅为 ComfyUI 添加 `--temp-directory /opt/ComfyUI/temp`，让其清理挂载点内的子目录。最终镜像 `local/minimax-h3-comfyui:v0.45.0` 的 ID 为 `sha256:1336c8b9d497b1fcdbe5ec848dbfbb01d29ba1e4d031f2c60e48432f91659e95`；重新验证了 GPU 算子、实际音频 VAE、`pip check`、非 root 启动及临时目录清理。此次参数修正未重复完整视频生成。

构建时为复用已完成的依赖安装缓存，指定 `DEPENDENCY_BASE_IMAGE=comfyui:spark`；该阶段只提供同为 Ubuntu 24.04 / CPython 3.12 的 venv 构建环境，所有 Python 包仍在全新 venv 内按锁文件安装。最终运行阶段基于上述 NGC 26.10 镜像，未使用旧镜像的 torch 或系统 Python 包。默认 Dockerfile 的两个阶段均使用 NGC 26.10。
